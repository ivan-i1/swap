Swap — how the Phaser 4 port works

What this page is. An orientation layer for an engineer who has not read the code. It explains how the 2013 Flixel + Box2D game in this repository runs on Phaser 4 in a browser and as an Android/iOS app. The code, web/README.md and web/MOBILE.md stay authoritative. Where this page and the code disagree, the code wins.

Checked against commit b71c719 on master (2026-10-21). This repo has no separate spec, schemas or ADRs. Every claim here comes from the source, from the README files, or from running the parser and test suite. This page does not mean anything is deployed. Nothing is published to a store yet.

Status labels are given as text as well as colour: Current in the code on master · Verify built, but not yet checked by hand · Deferred still owed by a person (keys, accounts, store listing) · Out of scope deliberately not ported.

1. Overview and boundary Current

The original ActionScript level files and assets → the port in web/ → the same game, frame for frame, in a browser or an app WebView.
The port does not redesign the game, does not edit the ActionScript project, and makes no network requests.

Does

Re-runs the 2013 beta (title, levels 1–20 with no level 13, end screen) with Flixel's player movement and Box2D's world physics, in the original update order.

Does not

Change level design, controls, tuning or quirks. Use Phaser's own physics. Hold any game state on a server.

Reads (read-only)

src/org/dinosaurriders/swap/levels/*.as, assets/ (CSV maps, PNGs, MP3s) and the Flixel font and button image, all in place in the AS3 tree.

Produces

A static bundle in web/dist/ served as-is to browsers. Capacitor copies the same bundle into web/android/ and web/ios/.

The one idea to carry through the rest of the page: the player is a Flixel object and everything else is a Box2D body. The player moves with Flixel's arcade movement and tile/box collision, and drags a Box2D body along so other bodies can feel it. Rocks, switches, fields and exits are simulated by Box2D (here planck.js). The original split responsibilities this way, and the port keeps that split rather than unifying it.

2. Stack and ownership Current

One job per component, and the thing each must not turn into. The "AS3 original" column is the file each one replaces, which is the fastest way to check a behaviour question against the source.

input/keyLatch.tsFlxG.keys Merges keyboard and touch buttons into pressed / justPressed / justReleased, sampled once per tick Per-scene input. It is one latch, registered once on the window.

Units: Box2D works in metres and the game in pixels, at Settings.ratio = 50 px per metre (settings.ts). A tile is 32 px (0.64 m). Default gravity is 10 m/s², which the player's Flixel acceleration sees as 500 px/s².

3. Walkthrough: one swap in Level 3 Current

Level 3 is the level that teaches the swap. This traces it from the level file to loading Level 4, using the level's real contents. Provenance: entity values are copied from Level_Level3.as and from running parseLevel on it. Code behaviour is cited by file. Masses were computed with the port's own formulas (as3MassData, density × area).

The cast in Level 3

  • Player starts at (0, 288).
  • Rock: a PolygonBody (SquareRock2, 32×32 px, 4 sides, density 2500) at (240, 384), swappable: true.
  • Weight switch #4 at (450, 408), required force 100.
  • Exit #5 at (600, 256), enabled: false, warp: "Level4".
  • Links: switch #4 → exit #5 onActivate: "ENABLE". Box #27 → hint #28 and box #29 → hint #30 showText.

    LevelContainer constructor
    Action

The one layer with hits: true (PlayerLayer) becomes the Flixel hit map plus one static Box2D box per solid tile, solid columns past both edges, and a kills row 5 tiles below the map.     Data

  5. Owner
    LevelScene.update
    Action
    Each animation frame adds Phaser's delta to an accumulator (capped at 2000/30 − 1 ≈ 65.7 ms, as FlxGame caps it). It runs keys.sample() + tick() once for every whole 16.67 ms, then render() once.
    Data
    Game time advances only in fixed ELAPSED = 1/60 s steps.
  6. Owner
    PropertyField #27
    Action
    The player walks right into box #27 (0, 120, 50×200). Box2D reports begin-contact. The field's link action runs and PhysicsUtil.enqueueText shows hint #28, replacing any hint already showing.
    Data
    On screen for TEXTDURATION = 4 s: "The S.W.A.P. spell lets me select glowing objects with the [S] key"
  7. Owner
    KeyLatch → Player.update
    Action
    S goes down (keyboard or the SELECT button). On the next sample justPressed('S') is true. The player adds fixture [3], a 1 × 1 m box sensor, plus the visible swap-area sprite.
    Data
    fixtures[3] = Box(0.5, 0.5), isSensor: true. It is removed on justReleased('S').
  8. Owner
    Player.onStartCollision
    Action
    The sensor overlaps the rock. The fixture is [3] and the other body is swappable, so the rock becomes the swap target and is marked selected. Any previously selected body is deselected.
    Data
    tempSwapObject = rock; rock.selected = true → glow turns green (0x66ff33).
  9. Owner
    Player.update → PhysicsUtil
    Action
    X pressed (justPressed('X')) with a target set: the swap is queued, not performed. Order matters: target first, player second, so the player's swap() is the one called.
    Data
    swapQueue = [rock, player], currentSkipCount = 0
  10. Owner
    PhysicsUtil.callSwaps, pass 1 (before the step)
    Action
    The skip count goes to 1 and both bodies are disabled for this step: invisible, with body.setActive(false). The world is not locked here, so physicsOp runs immediately.
    Data
    Neither body collides during this frame's world.step(1/60, 10, 10).
  11. Owner
    PhysicsUtil.callSwaps, pass 2 (after the step) → Player.swap
    Action
    The skip count reaches SWAPSKIPCOUNT = 2. Both bodies are re-enabled, then the player calls swap(rock): positions exchange, velocities exchange, a SwapTrail is drawn at both spots, and a 1 s cooldown starts (SWAPCOOLDOWN, a FlxTimer).
    Data
    Player at the rock's old centre, rock at the player's. The velocity copy keeps the original's unit mix (m/s into px/s), so a resting rock hands the player near-zero speed. All of this happens within one tick: the swap is visible in the very next render.
  12. Owner
    WeightSwitch #4
    Action
    Every body contact adds mass × |gravity| and every contact end subtracts it. At or above 100 the switch activates, and the onActivate: ENABLE link sets exit.enabled = true (visible, body active). Below 100 it disables the exit again.
    Data
    Computed with the port's formulas: player 71.5 kg × 10 = 715, rock 1024 kg × 10 = 10 240. Either one clears 100 alone.
  13. Owner
    Exit #5 → LevelContainer → LevelScene
    Action
    A player contact with the active exit sensor calls exitLevel("Level4"). At the end of the tick the container records its outcome, the scene stops ticking, and the level restarts with the next name.
    Data
    TypeScript value, from LevelContainer.ts (not a wire format) 
    outcome = { kind: 'restart', level: 'Level4' }  →  scene.restart({ level: 'Level4' })

4. Contrast: dying and restarting Current

The boundary case. There is no lives counter and no game-over screen. Every death, and the R key, produces the same outcome: rebuild the current level from its file.

  1. Owner
    Box2D contact → Player
    Action
    Three ways an attempt ends:
    • touching any body with kills: true, such as tiles 14/15 or the kill row under the map;
    • being crushed: after the solve, if normalImpulse × 60 > MAXFORCE (10 000);
    • pressing R, which tick() checks directly without killing the player.
    Data
    Deaths: player.kill() → onKill callback → reset(). R: reset().
  2. Owner
    LevelContainer.reset
    Action
    Records the outcome once (??=), so a second death in the same tick changes nothing.
    Data
    { kind: 'restart', level: 'Level3' }
  3. Owner
    LevelScene
    Action
    scene.restart throws away the whole container: planck world, timers, PhysicsUtil, sprites. The key latch is window-level rather than per scene, so a key held on the keyboard is still held in the rebuilt level.
    Data
    Nothing carries over between attempts except the key latch.

The last level has a PropertyField with endgame: true. Entering it sets the outcome to { kind: 'endgame' }, which shows "Thank you for playing" and returns to the title after 5 s.

5. The core mechanism: one frame Current

The reason the port plays like the original is that LevelContainer.tick() repeats Flixel's frame order exactly. Reordering any of these steps changes gameplay (jump feel, swap timing, crush deaths). Read the method itself before moving anything.

  1. Clock += 16.67 ms. Plugins: TimerManager.update, then the player's FlxControl (walk acceleration 500, top speed 150 px/s, drag 800, jump 265 px/s, 200 ms coyote time).
  2. Members in insertion order: preUpdate → update → postUpdate. Box2D bodies copy their position from the world and add their own gravity force. The player instead pushes its Flixel position into its Box2D body.
  3. FlxG.collide(player, spriteGroup): Flixel separation of the player against solid sprites and the hit tilemap.
  4. PhysicsUtil.update: swap pass 1, destroy queued bodies, apply queued rotations, buoyancy.
  5. Buoyancy again, then world.step(1/60, 10, 10). The AS3 world ran its controllers inside Step(), so buoyancy is applied twice per frame in the original too.
  6. Deferred physics ops: mutations requested inside contact callbacks run now. planck forbids them mid-step; AS3 Box2D allowed them. Same frame, same order.
  7. Swap pass 2, then R / exit / death outcome checks, then the camera (platformer deadzone, clamped to the map) and the screen-flash fade.

Flixel side (player)

Arcade velocity, drag and max speed; axis-separated AABB collision with an overlap bias of 4 px. Pure functions in flixel/core.ts, unit-tested.

Box2D side (world)

Everything else. Contacts are routed to each body's onStart/onEnd/onBefore/onAfterSolveCollision through the fixture's userData.

Where they meet

The player's Box2D body carries the AS3 mass (71.5 kg). AS3 counted the clockwise foot sensor as negative area. planck would re-wind it and get a different mass, which would change pushing, switches and crushes, so the mass is set explicitly.

7. The app shell: touch, Android, iOS Verify

Capacitor copies dist/ into a native project that shows it in the system WebView (Chromium on Android, WKWebView on iOS). Phaser runs exactly as it does in a mobile browser, so nothing is translated between native code and the game. The only native-aware file is native.ts, and it does nothing in a browser.
